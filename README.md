# 2D图像到3D打印模型Agent工作流

大数据实训课程P05项目。第一版面向简单摆件，将单张物体图片转换为经过网格修复、尺寸校准、可打印性检查和人工切片确认的STL模型，并输出GLB预览与质量报告。

## 项目材料

- [项目规则](AGENTS.md)：每次小变更遵循课程9步流程，明确范围、验证、记录和提交纪律。
- [唯一当前任务P0](spec/当前开发任务.md)：重建执行环境与工具可行性验证，状态为待启动。
- [下一任务P1](spec/未来规划.md)：契约和固定样例；未来任务文件只保留这一项。
- [已完成任务](spec/已完成任务.md)、[Bug记录](spec/bug调试文档.md)：记录完成内容、问题、验证和遗留限制。
- [架构设计](doc/架构设计.md)、[接口与字段](doc/接口与字段.md)：模块、工具、状态与字段的权威说明。
- [评估设计与记录](doc/评估设计.md)、[AI协作记录](doc/AI协作记录.md)：指标、前后结果、失败和人工复核记录。

- [技术方案与分阶段开发计划](技术方案与分阶段开发计划.md)：第一版范围、技术选型、模块职责、状态/API、20个工作日开发顺序及验收标准。
- [课程规划与开发规范](<Agent开发课程实验课题总体规划与开发规范(3).md>)：课程原始要求，重点参考第2章、第5.1节和第5.6节。

## 当前进度

当前已建立技术方案、AGENTS.md及7类长期记录文档。唯一当前阶段为P0，状态为待启动；下一项仅P1。本轮只维护并提交文档，不安装模型、不下载权重、不创建业务代码，也不运行模型或切片验证。后续P0须在小组选定的执行机器上验证，当前文档完成不表示技术验收通过。

推荐技术路线：Python3.11、FastAPI、Pydantic、LangGraph、TripoSR、Trimesh、Blender、React/Three.js。采用单worker执行GPU任务，第一版不训练模型，不实现多视图融合和打印机控制。

## 仓库约定

- 仓库保持私有，组员访问权限按实际需要添加。
- 仅提交源代码、文档、评估摘要和小型授权测试样例。
- 密钥、模型权重、虚拟环境、本地数据库及完整运行产物不入库。
- 开发时逐次执行AGENTS.md中的9步流程，只维护一个当前任务和一个下一任务；记录真实测试、评估、Bug、人工复核和完成结果，不把AI自查当作人工复核。
