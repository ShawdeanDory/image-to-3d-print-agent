## 1.交付和边界

本机交付目录：`runs/print-demo-20261029-01/交付/`，压缩包为同级`小鸭120mm_打印展示包.zip`。包含打印STL、无纹理打印GLB、原始彩色GLB、实际模型预览、说明和质量/切片JSON，共6文件。原件摘要保持，不重烘焙；打印副本允许必要拓扑和有限厚度变化，不能称其保留原UV/PBR。

本轮交付独立转换工具和这一件展示模型，未修改网页、API、LangGraph或生产默认策略。TRELLIS.2常驻继续保持，33个旧任务上下文/响应/状态完全保持。后续是否接入所有新任务另行确定，不把本单例说成通用修复器或批量成功率。

## 2.参考方法和实现

完整论文/代码/许可索引见[算法参考](打印修复算法参考与接入.md)。实际采用：

1. MeshFix/PyMeshFix0.18.1修孔和拓扑；关闭默认删小组件与连接组件。对已闭合壳使用MeshLib的包含判定，只有被其他闭合壳完全包含的内腔才填实，外部独立主要部件不默认删除。小鸭原来的两层相近壳会形成薄壁，填实只作用打印副本。
2. 同一Blender/Toolbox复检后，因31处薄壁及底面失败，使用MeshLib-Core3.1.4.297作0.7mm有限外偏移、0.35mm体素、最大0.06mm简化误差；底部仅切平0.5mm，不添加底座。切口局部CutAndFill后再次定标到120mm并完整复检。两轮版本都保留。
3. 已有UV/PBR不能逐点对应新的拓扑，故打印副本明确为无纹理几何；首次彩色GLB原字节保留。没有启用Paint3D、额外模型、重烘焙或材质生成。

实现：[print_demo.py](../src/image_to_3d_print/print_demo.py)、[隔离原生算法](../scripts/tools/print_repair_worker.py)、[切片验证](../scripts/tools/verify_print_demo_slicing.py)、[配置示例](../config/print-demo.example.json)、[版本与官方PyPI摘要](../locks/print-demo-tools.json)。原生工具只装在独立目录，不改变模型/后端基础环境；上游库源码及二进制不入库或启动包。MeshFix引用Attene2010，MeshLib为教育/非商业运行时许可，不把它冒称该论文的完整复现。

## 4.验证与失败保留

- 本机完整离线291通过/14项平台或原生依赖条件跳过（74.95秒），Linux原生专项13通过（1.45秒），实际G-code包含448段支撑主体/383段支撑接触。完整结果见[实证](evidence/print-demo-20261029/result.json)。本轮不需要前端构建或浏览器测试，因为未改前端/服务。
- 正常闭合体、复杂孔、两个外部主要物体拒绝、外形丢失拒绝、内腔填实、无挤出/错误高度/缺层、支撑中间层和配置边界分别验证。真实展示件的修复、Blender和切片不使用替身。
- 通用复杂件的MeshFix试验虽然水密却丢失约12%宽/深，未采用为当前展示结果；小鸭零偏移体素候选超过500万面被拒绝；初次底部封口造成自交，局部修复后重新检查，不降低阈值。
- Linux旧AppImage缺图形库，未写切片通过；停止扩装，明确使用本机既有2.9.6。切片初次校验误把总路径层数固定为600，遗漏支撑中间层；保留失败，补回归后验证层高连续、实际672层及最高120mm。第一次G-code/报告保留，重跑记录另存`slicing-verified/`。
- 逐点Rtree包含探针耗时过长，已核对并停止其专属进程；正式转换改用闭合网格包含判定。原生测试初次误读祖先pytest配置导致旧源码导入失败，补隔离配置后专项通过。

## 5.可复现命令与如何打印

云端既有CPU环境准备（模型环境不重装；先核对[许可和锁定](打印修复算法参考与接入.md)）：

```bash
runtime/envs/backend/bin/python -m pip install --no-deps --target runtime/print-repair-deps/pymeshfix-0.18.1 pymeshfix==0.18.1
runtime/envs/backend/bin/python -m pip install --no-deps --target runtime/print-repair-deps/meshlib-core-3.1.4.297 meshlib-core==3.1.4.297
PYTHONPATH=src runtime/envs/backend/bin/python -m image_to_3d_print.print_demo \
  --source /绝对路径/已有原始模型.glb --frame y_up --height-mm 120 \
  --settings runtime/config/backend.json --native-config config/print-demo.example.json \
  --output /绝对路径/尚不存在的新输出目录
```

只接受100～150mm的本轮展示范围；输出已存在则拒绝覆盖；最多2轮，每次原生调用180秒上限，超时终止本轮进程组。失败返回明确错误，旧文件和日志保持。输入坐标必须按实际生成文件指定，不能把GLB原始Y朝上与已带逻辑变换的检查文件混用。

本机实际切片/检查命令：

```powershell
$env:PYTHONUTF8='1'
runtime/envs/backend/Scripts/python.exe -m pytest tests -q
runtime/envs/backend/Scripts/python.exe scripts/tools/verify_print_demo_slicing.py --root runs/print-demo-20261029-01/duck-demo-final --attempt slicing-verified
```

实际Linux原生专项需显式设置`I3D_PRINT_NATIVE_CONFIG`为配置文件绝对路径，再运行`pytest tests/geometry/test_print_demo.py tests/geometry/test_print_native.py -q`。本机未安装原生依赖时按平台跳过，不冒充已验证。

把交付包中的STL交给打印人员，以其实际打印机配置重新切片，核对支撑、底面方向和床面空间。当前G-code仅为演示验证，不作为未知打印机的可直接执行文件，所以交付包不含它；颜色由耗材决定，STL不包含PBR颜色。演示估时约14.5小时，安排展示前需给打印和去支撑留出时间。
