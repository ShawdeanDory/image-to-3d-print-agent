# 造物工坊：队友启动包使用说明

这是Windows10/11的64位客户端。完整解压、完成一次SSH授权后，即可双击“启动造物工坊.exe”。网页和Node运行程序已随包提供，不用安装Node、Python、npm、Git或模型，电脑也不需要GPU。模型在组长的AutoDL实例上执行。

## 1.先解压到一个固定文件夹

右键ZIP选择“全部解压”，例如解压到D:\造物工坊队友。不要在压缩包里直接运行exe，不要只拖出exe，保留config、frontend、scripts、tools和licenses目录。

- 首次配置.cmd：生成你自己的SSH密钥，并写入本机连接配置。
- 启动造物工坊.exe：启动连接并打开网页，以后使用双击这个。
- 使用说明.txt：可用记事本查看本说明；Markdown版内容相同。
- config/team-connection.json：服务器地址、SSH端口、用户名、服务器公钥；均不是API密钥。
- config/launcher.example.json：云端部署路径、本机网页/隧道端口；通常不需要修改。
- tools/node：已经准备的Node运行程序及许可证。
- frontend：当前网页构建及Vite运行文件，不能删除。

Windows需要已有.NET Framework4.x及“OpenSSH客户端”。若提示找不到ssh.exe或ssh-keygen.exe，在Windows设置中搜索“可选功能”，添加“OpenSSH客户端”，关闭后重新打开首次配置；不要安装成“OpenSSH服务器”。该步骤可能需要管理员或系统管理员协助。包内不会自动修改系统功能。

## 2.首次配置你自己的连接权限

1. 双击“首次配置.cmd”。脚本执行策略只对这次PowerShell进程生效，不修改系统策略。
2. 等待显示“配置完成”。专用SSH密钥自动生成在你自己的Windows用户目录：`%USERPROFILE%\.ssh\image3d_team_ed25519`。此密钥无口令，供启动器后台登录；已有同名密钥不会被覆盖。
3. 文件夹中出现“发给组长的公钥.txt”。把这个txt发给组长，里面只含ssh-ed25519公钥。
4. 等组长回复“公钥已授权、实例已开机”，再启动exe。

私钥保留在你的Windows用户目录，不在此压缩包内。不要发送没有.pub后缀的私钥；无需向组长索取他的私钥、AutoDL账号密码、HF令牌或DeepSeek密钥。云端模型和API配置继续由已有服务读取。

重复运行首次配置会复用自己的同名密钥并更新本机路径，不能拿另一位队友已配置过的SSH配置直接使用。包内路径是按你自己的用户目录生成的，不依赖组长电脑路径。

### 组长如何授权这份公钥

组长在AutoDL控制台的JupyterLab终端操作。下面仅是需要组长手动执行的示例，不会由启动包自动执行。

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
cat >> ~/.ssh/authorized_keys <<'PUBLIC_KEY'
把队友txt内ssh-ed25519开头的完整一行粘贴到这里，替换本行
PUBLIC_KEY
chmod 600 ~/.ssh/authorized_keys
```

只追加队友公钥，不覆盖现有authorized_keys。不要把说明占位行直接执行。此连接使用云端root账号，因此只向需要使用该实例的可信组员授权。已有成员以后无需重复追加。

## 3.确认服务器身份和最新地址

包内config/team-connection.json默认保存打包时本机已信任的服务器公钥。首次配置把这份公开信息写入你自己的`%USERPROFILE%\.ssh\image3d_team_known_hosts`，启动器保持严格验证，不自动接受其他服务器。

默认登录信息是：

```text
主机：connect.cqa1.seetacloud.com
SSH端口：44075
用户名：root
```

这是打包时配置，不代表此刻实例一定已开机。若AutoDL控制台登录命令变化，先向组长索取更新后的config/team-connection.json，再运行首次配置。服务器密钥不匹配时应请组长核对，不要直接清空所有known_hosts或关闭严格检查。

如果拿到的包中host_key为空，需要先向组长核对服务器公钥指纹。在解压目录打开PowerShell，手动执行：

```powershell
ssh -F .\runtime\ssh\p2a_config -o StrictHostKeyChecking=ask p2a-autodl "echo SSH_OK"
```

确认终端显示的SHA256指纹与组长提供的相同后，才输入yes。显示SSH_OK后再运行exe。这个命令仅用于已取得授权的首次连接，不会安装模型。

## 4.以后如何打开和使用

1. 请组长手动启动同一AutoDL实例，确认是正常GPU模式。
2. 双击“启动造物工坊.exe”，等待“已连接计算服务”。程序会检查并按需补启动已有API/单worker、建立SSH隧道、启动本机网页并自动打开浏览器。
3. 网页地址默认是http://127.0.0.1:5173/。这个地址指向你自己的电脑，不能把它当作公网网址发给别人。
4. 保留启动器窗口，可以最小化。断线时先确认实例开机，再点启动器的“重新连接”。网页里的重连本身不能启动云端进程。
5. 上传图片和参数后等真实处理结果，完成后点下载按钮；启动器本身不会自动提交图片任务。
6. 用完关闭启动器即可停止本次在你电脑上创建的网页/隧道进程。关闭窗口不会取消已提交的云端任务，也不会关闭AutoDL；需要停止自己的任务时先在页面取消。实例仍由组长手动关机。

所有成员共用同一个云端服务、任务存储和单worker/GPU，提交的任务会排队。不要因为排队反复提交相同图片；这不是每人独占一张GPU的部署。当前按组内共享使用，未新增成员账号隔离。

## 5.常见问题

| 提示或现象 | 处理 |
| --- | --- |
| 尚未配置SSH | 先双击首次配置.cmd，并把公钥交给组长授权 |
| Permission denied(publickey) | 确认组长添加的是本人的完整公钥，且实例、用户名、端口正确；不需要填写组长密码 |
| 连接超时或拒绝连接 | 确认实例已开机、网络可达，并核对AutoDL最新SSH命令；启动器不会自动开机 |
| 服务器公钥不匹配 | 联系组长核对服务器指纹，不能绕过验证 |
| 找不到ssh.exe | 安装Windows可选功能“OpenSSH客户端”，然后重开首次配置 |
| 缺少Node或网页文件 | 重新完整解压原ZIP，保留tools和frontend；不要只复制exe |
| 9000或5173端口被占用 | 先关闭自己之前的启动器；若是其他软件占用，可修改config/launcher.example.json中的tunnel_port/ui_port为两个不同的空闲端口 |
| 云端缺少部署或环境 | 请组长检查已有云端项目；此包不会重装模型或切换其他实例 |
| API要求额外访问令牌 | 联系组长核对现有服务认证，包内没有令牌，不会绕过认证 |
| 网页出现历史任务 | 浏览器可能保留自己上次的任务ID；不代表启动器重新生成了模型 |

错误日志可从启动器“查看日志”打开，位置是解压目录runtime/launcher。反馈时提供错误信息，发送前查看是否含自己的路径等信息；不要发送私钥或API密钥。

## 6.包内范围和验证边界

包内只含启动器、必要脚本/公开配置、网页、Node/Vite运行文件及第三方许可证。不含组长的私钥、API密钥、HF令牌、模型权重、数据库、业务图片、模型文件或运行日志。

首次使用后才在你的电脑产生runtime配置/日志及用户目录密钥。以后转发给新队友时，发送收到的原始ZIP，不要重新压缩已使用目录。

该包复用现有业务接口和云端部署；不更换后端、不改变当前原始PBR交付或打印结论。网页/代理的固定本机检查不等于已验证你这台新电脑的SSH授权，也不等于模型生成或可打印验收。最终连接须在组长授权公钥、实例开机后完成。
