# AutoDL云端复现实验准备

- 日期/版本：2026-10-19，v1.0；关联DOC-004。
- 用户已确定：使用[AutoDL算力市场](https://www.autodl.com/market/list)，准备选择20GB或24GB显存。
- 本项目建议：优先单卡24GB；在费用、镜像和实际供应明确后选择实例。具体实例信息尚未提供，本轮没有租用、连接或执行云端推理，所有云端模型结果均为“未验证”。
- 本文件是迁移准备，不是已执行的安装手册。当前阶段与停止点见[当前任务第9节](../spec/当前开发任务.md#9doc-004论文调研归档与云端复现准备)；论文依据与完整度见[调研报告](论文调研与推荐路线.md)。

## 1.20GB与24GB如何选择

| 显存意向 | 首轮新候选 | 官方依据与本项目安排 |
| --- | --- | --- |
| 20GB | TripoSG；TRELLIS可作为后续可选对照 | TripoSG要求至少8GB/模型卡大于8GB，TRELLIS要求至少16GB；先做TripoSR迁移冒烟，再只验证一个新模型；实际GPU兼容性另测 |
| 24GB，优先 | TRELLIS.2；若具体环境验证失败再记录原因、重新确定候选 | TRELLIS.2要求至少24GB，20GB不满足官方门槛；满足标称容量不代表所有分辨率或参数都能运行 |

作者硬件要求来自[TripoSG](https://github.com/VAST-AI-Research/TripoSG)、[TRELLIS](https://github.com/microsoft/TRELLIS)、[TRELLIS.2](https://github.com/microsoft/TRELLIS.2)。不默认采用社区量化、非官方权重或CPU换出配置来宣称20GB满足24GB门槛。

在AutoDL市场可优先筛选单卡RTX4090的24GB档；RTX3090的24GB档可按实际报价和环境条件比较。平台官方GPU选型页列有这两种规格，但本轮没有获取到可确认的实时市场库存和成交价格，不能承诺某地区有货或引用历史单价作为预算。[AutoDL官方GPU选型](https://www.autodl.com/docs/gpu/)

CPU、内存和磁盘同样要查看。项目建议先筛选至少8vCPU、32GB内存、100GB可用数据空间，条件允许时增加编译/权重缓存余量；这些是项目规划建议，非论文公布的最低要求，实际占用需记录。只需单卡串行推理，不为本次验证选择多卡训练配置。

## 3.目录、存储和环境安排

建议在实例数据盘中使用`/root/autodl-tmp/image-to-3d-print-agent/`作为项目根目录，沿用仓库既有`runtime/`、`weights/`、`runs/`布局。该路径是待执行的目录建议，本轮未创建。

| 材料 | 安排 |
| --- | --- |
| 项目代码、文档、固定小样例 | 从现有私有仓库检出明确提交；授权访问按现有凭据流程，不将令牌拼入仓库URL |
| 各模型运行环境 | 逐个独立环境，不混装TripoSR、TripoSG与TRELLIS.2依赖；实际验证后生成Linux环境快照 |
| 上游源码 | 放在项目`runtime/upstream/`，记录完整提交与子模块；保留来源及修改说明 |
| 权重和缓存 | 放在受Git忽略的`weights/`或`runtime/cache/`，固定revision；原始权重不入库 |
| 执行证据 | 每次新建`runs/`执行目录，保留输入、命令、日志、参数、网格和退出码；不能覆盖本机历史结果 |
| 交接与备份 | 代码/脱敏摘要提交Git；原始网格和运行日志另行备份到用户选定位置，不能只靠镜像保存数据盘 |

AutoDL官方文档区分系统盘、`/root/autodl-tmp`数据盘及文件存储；普通实例的数据盘不包含在系统镜像中。实例类型可能有差异，选定后再核对实际挂载和迁移规则；不能只保存镜像就认定权重、数据盘和结果已备份。[环境与磁盘](https://www.autodl.com/docs/env)、[镜像说明](https://www.autodl.com/docs/image/)、[文件存储](https://www.autodl.com/docs/fs/)

## 4.本机成果如何迁移

原有[P0锁定记录](../locks/README.md)是Windows实测快照：含`.exe`工具、`Scripts/python.exe`路径和Visual Studio构建步骤。它提供模型/工具版本依据，不是可直接在AutoDL的Linux镜像中照抄的安装命令。

本轮只读检查发现以下已知平台绑定点，后续获准适配时再作最小变更，不将其记录为本机Bug：

| 已有位置 | 迁移注意点 |
| --- | --- |
| `scripts/p0/verify_reconstruction.py` | 调用Windows的`Scripts/python.exe`；云端需要明确Linux解释器路径，当前没有已验证的跨平台包装器 |
| `scripts/p0/build_torchmcubes.py` | 固定Visual Studio路径、Windows构建和安装入口；不能在Linux执行该流程 |
| `scripts/p0/verify_slicing.py` | 切片程序路径是Windows的`prusa-slicer-console.exe`；须明确检查/切片在云端还是本机执行 |
| `scripts/local_preview/launcher.py`和根CMD | 依赖本机选图窗口及Windows Blender；本轮不把它改成远程上传或云端任务入口 |
| `scripts/p0/reconstruct_case.py` | 使用模型、缓存及固定参数，有离线缓存前置要求；Linux导入、扩展和权重加载尚未验证 |

可以先将云端生成的GLB下载回本机Blender预览；几何检查与切片证据仍需对应这份云端网格的具体版本。云端没有图形桌面时，不把“脚本退出正常”写成人工已经看过模型。

## 5.后续验证顺序与门槛，尚未执行

### 5.1环境冒烟

实例和预算确定、具体验证范围写入当前任务后，先保存安装前的GPU、驱动、GPU计算能力、可用显存、CPU/内存/磁盘、操作系统、镜像和编译工具信息。再按所选模型官方说明建立隔离环境，验证CUDA张量运算、原生扩展、模型加载及文件读写，保留实际命令和返回码。

TRELLIS.2官方安装默认使用PyTorch2.6.0/CUDA12.4，不能从本机PyTorch2.5.1/CUDA12.1直接推断新环境兼容。实际版本由所选GPU、驱动和编译结果确定并锁定；如果需要改变预算、机器或后端，先记录原因和预期，不静默切换。[官方安装要求](https://github.com/microsoft/TRELLIS.2)

### 5.2同机工程基线

先在AutoDL复跑[P0汉堡/机器人输入](../fixtures/p0/README.md)，以原有TripoSR源码、权重和低显存参数为工程对照。CPU/GPU等值面提取方式及Linux依赖差异单独记录。原本机成功记录保留，不把新机器写成已通过；不拿本机旧耗时与云端新耗时直接计算模型加速比。

### 5.3官方新模型基线

先固定所选官方代码完整提交、子模块、权重revision、依赖、参数和随机种子，独立执行官方样例。保存原始输出并用独立工具读回；只有这一步实际通过，才使用同组项目输入开展比较。官方默认设置与低显存变体/后续适配分别命名，不能混记为同一基线。

### 5.4项目对照与小改进

对同组图片固定输入来源、前景处理口径、目标高度、几何工具和打印配置；记录原始网格及全部失败。一次只引入一个有明确问题依据的改动，再比较质量、时间、显存和缺陷。修复、定标或导出业务实现仍须按阶段授权推进，本轮不提前实现。

评价口径与门槛继续引用[评估设计](评估设计.md)，不在迁移计划另设成功率或降低质量阈值。GPU分配/预留显存与`nvidia-smi`整体占用分开记录，下载/编译与推理计时分开。

### 5.5输出与停止

环境失败、显存不足、超时或缺工具都保存原始错误、日志和退出码；未执行项保持未执行，不把失败输出包装为成功。具体重试次数、单次推理和环境准备预算应在云端启动前写清，不沿用已经结束的本机P0授权来无限重试。

| 证据 | 应记录的内容 |
| --- | --- |
| 运行身份 | 日期、执行机代号、实例/GPU、项目/上游提交、模型revision、依赖、输入和参数 |
| 基线结果 | 官方样例与项目固定输入分开；命令、加载/推理/提取时间、峰值显存、退出码和原始网格 |
| 几何与切片 | 原始/修复/定标网格版本、检查项实测、打印配置、对应分层预览与人工确认 |
| 变更归因 | 具体问题、修改前证据、最小改动、前后比较、失败分类和遗留限制 |
| 交接 | 可重现命令和Linux版本快照入库；完整产物与权重另存；费用、备份和停机状态据实记录 |

本轮停止于资料归档和GitHub同步。AutoDL平台及20GB/24GB意向已经确定，实际实例、访问、费用预算和云端验证启动范围待补；P0历史验收保持，P1未启动，当前没有已实现的远程服务。
