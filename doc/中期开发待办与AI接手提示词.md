## 2.论文基础和小组改进如何定位

项目在现有论文、预训练模型和几何工具上继续开发，重点是把单图生成能力变成满足打印约束、可交互、可核验的应用。

| 层次 | 使用已有工作的部分 | 小组负责的部分 |
| --- | --- | --- |
| 图像到网格 | TripoSR、TRELLIS.2官方代码及预训练权重 | 动态图片接入、固定适配器、版本/资源/失败记录 |
| 几何与打印 | Trimesh、Blender、打印检查和切片工具 | 受限修复、毫米定标、检查门槛、版本对照和文件验证 |
| Agent应用 | 工作流框架、语言模型和现有公共契约 | 需求澄清、证据分支、确认、检查点恢复、停止和前后端交互 |
| 实验证据 | 已有固定输入与测量协议 | 同后端前后对照、交互轨迹、失败保留和改进归因 |

目前可称“官方预训练推理复现与工程适配”；没有已验证的重建算法改进、重新训练、微调或论文数值表复现。官方T形零件只验证环境与执行路径，不能替代简单摆件质量或打印验收。若汇报某篇论文的特定结果图，需另外核对原文图号、输入和设置。

后续可验证的改进包括尺度正确性、已支持缺陷的处理、检查完整性、可交付率、追问正确性和减少重复重建。比较这些改进时固定生成后端，不能把换模型带来的差异算作Agent改进。

## 3.第一版完整工作流的边界

输入为单张PNG/JPEG、单个不透明且轮廓清晰的非功能性简单摆件。高度、朝向和打印配置需要明确；先沿用项目演示打印配置，不把它说成已确认的实机参数。

完整流程包含成功交付、等待补充、修复确认和明确失败。必需检查失败或未执行时不能标成功；候选STL通过独立读取后仍需其自身的人工预览与切片确认。没有打印机的现状保持，物理打印结论单独记录。

不增加第三个候选，不重现论文训练，不将多视图融合、3MF、任意薄壁加厚、自动底座、自动支撑、复杂机械配合和直接控制打印机加入本轮目标。单张图片生成的近似形状不能被描述为精密实物复原。

~~~mermaid
flowchart TD
    A[上传图片与需求] --> B[图片检查与去背景]
    B --> C{尺度和朝向明确}
    C -->|缺信息| D[追问并保存任务]
    D -->|补充后恢复| C
    C -->|明确| E[真实重建与原始网格初检]
    E --> F[受限修复与毫米定标]
    F --> G{打印检查}
    G -->|支持修复| H[确认修改并生成新版本]
    H -->|最多两轮并复检| F
    G -->|无法处理或到上限| I[说明原因并停止]
    G -->|通过| J[模型预览与候选STL]
    J --> K[人工切片及证据提交]
    K --> L[最终报告与交付结论]
~~~

## 5.实施顺序与依赖

1. 核对本机代码及云端已有成果，补齐相机/测量和人工复核；同时明确下一轮具体功能、授权与负责人。
2. 在单一公共契约上安排工具适配、工作流/服务和前端协同。前端可围绕接口先开发，正式联调必须使用真实服务。这个协同顺序是中期实施建议，启动时需写入唯一当前任务，不能靠本文件自动改写原阶段验收顺序。
3. 在既有两个后端上完成范围内选型，正式展示和完整路径固定后端/版本；不因官方T例好看而直接认定候选胜出。
4. 打通“上传→需求澄清→真实重建→修复定标→检查→预览/候选导出→切片确认→报告”，并完成失败、等待、恢复和取消分支。
5. 运行中期真实轨迹和局部对照，修复发现的问题，再准备演示。最终冻结评估单列，保留集不用于调参。

本次仅归档上述规划，不实现业务或执行云端命令。后续组员发出明确的功能实施指令后，接手AI应结合该轮授权，在当前任务记录具体目标、样例、基线及停止点；已有明确授权不反复询问。清单本身不授权任意新阶段、账号操作、实例开关机或长时间模型任务。

共享文件包括当前任务、公共schema、接口文档、评估协议和依赖配置。修改前核对其他成员的进行中改动；不回滚他人内容、不强制推送。每个小变更按仓库规则交付，交接注明提交、文件、实际命令、结果、未测项和待人工内容。模块划分不代表允许AI自动生成多个独立聊天或代理。

## 7.中期原型怎样才算完成

| 场景 | 必须观察到的真实行为 | 主要证据 |
| --- | --- | --- |
| 正常简单摆件 | 页面上传本次图片，完成确认、真实重建、定标、必需检查、STL重读及实际切片确认 | 同一任务的图像、原始/修复网格、尺寸、检查、STL和分层证据 |
| 缺高度或单位 | Agent提出具体问题，任务等待；补充后恢复，不重复已完成的重建 | 待补项、状态轨迹、前后工具调用记录 |
| 结构修改确认 | 提示具体影响，确认后生成新版本并复检 | 确认记录、前后网格、操作参数和检查差异 |
| 薄壁等阻断缺陷 | 检查器实际发现问题，系统说明并停止合格交付 | 对应缺陷证据、检查失败项和终态 |
| 取消、超时或工具失败 | 任务正确停止，保留已有结果，不继续调用后续工具 | 错误、退出情况、事件与进程处理记录 |

至少保留正常、缺尺度恢复、阻断缺陷三类真实轨迹及至少一次真实语言模型交互；完整工具链先按既有要求验证至少3个正常对象、至少1份对应候选STL有效分层。修复确认也需实际走通。取消/超时/修复上限允许用确定性故障样例回归，不能把它写成真实GPU运行。

具体最终成功率、尺度、轮廓、拓扑和5个对象切片等门槛继续以[评估设计](评估设计.md)为准，未在本文件下调。中期可以报告小批真实结果，不把它外推成最终成功率。真实缺陷无法在受限范围处理时，应完成“发现并正确停止”的流程，不强行承诺所有图片都可打印。
