# 几何工具接口与接手说明

- 实现：工具包0.2.0，内部工具schema0.1；公共契约1.0.0、20个模型保持。
- 主入口：[commands.dispatch](../src/image_to_3d_print/geometry/commands.py)；可信操作者入口：[geometry_cli.py](../scripts/tools/geometry_cli.py)；机器定义：[内部工具schema](../schemas/geometry-tools-v0.1.schema.json)。本文件不定义第二套HTTP字段。
- 本方向提供Linux工具，不包含FastAPI、LangGraph、SQLite、前端、账号鉴权或切片确认服务。禁止把开发验证脚本当作完整Agent。

## 1.工作流成员怎样调用

```python
from image_to_3d_print.geometry.commands import ToolConfiguration, dispatch

# root为本应用存储目录；configuration由服务端读取，不交给LLM或前端覆盖。
configuration = ToolConfiguration.model_validate_json(config_file.read_text())
outcome = dispatch(root, command, configuration, cancel_event=cancel_event)
```

command必须通过内部Pydantic联合模型；额外字段、任意命令和越界相对路径拒绝。run_id由任务服务创建，网格用mesh_version引用；图片用asset_id。HTTP上传接口接收字节后调用AssetStore.save，不能将客户端磁盘路径传给工具。CLI的import_image只面向可信操作者、读取项目内已放置文件，不是上传服务。

| operation | 关键输入 | 输出/分支 |
| --- | --- | --- |
| import_image | source为项目内合法图片 | 公共AssetRecord；原始字节保存，不改变原图 |
| prepare_image | asset_id；普通图显式background_backend | 原图、256方形透明前景、单通道蒙版、边界提示及review_required |
| reconstruct | backend、prepared_outcome、具体InputReview | 原始网格版本、独立初检、输入/版本/时间/显存/日志；缺配置不切换 |
| clean | mesh_version | 清重复/退化、修法线的新版本；修复轮数加1 |
| scale | mesh_version、公共ModelTaskRequest | 确认轴向、等比毫米定标、最低点Z=0；不改变修复轮数 |
| inspect | mesh_version、公共PrinterProfile、确认高度、可选BedReview/ComponentReview | 公共MeshInspection、逐项CheckResult、verdict；工具失败保留not_run |
| preview | mesh_version | CPU诊断PNG；不替代用户确认或打印判断 |
| measure_view | mesh_version、mask_path、backend | 只读取服务端登记的固定映射；未人工复核时质量指标not_run/null |
| propose | mesh_version、StructureRequest | 指定补洞/组件删除/简化的提案、PLY/GLB预览、来源/变化；不应用 |
| confirm | proposal_id、人工决定 | 仅人工接口允许；确认绑定提案、源版本和预览摘要 |
| apply | proposal_id | 未确认/拒绝/过期均阻断；成功追加版本，重复调用返回已有版本 |
| export | mesh_version | 毫米STL、米制Y朝上GLB及独立逆变换重读，task_success始终false |

返回为[ToolOutcome](../src/image_to_3d_print/tools.py)：tool、artifacts、evidence。tool.succeeded仅代表该工具执行完成。将每轮产物/证据合并进同一任务，再用公共响应模型核对引用；不得仅凭一个工具布尔值把任务判成功。

## 2.确认、引用和状态边界

1. 创建前调用公共validate_request_references，使用服务端资产、打印配置及测量证据登记表。measured_object的证据ID必须真实存在，不能只有字符串；工具不替应用证明“用户确实量过”。
2. req.pending_inputs非空时由工作流追问并保存，不调用定标；补尺寸/姿态后复用原网格。InputReview应引用本任务具体前景，不能由模型自行填写“用户已确认”。不确定/超范围时请求换图或人工判断。
3. 结构确认节点与apply节点分开。人工接口核对当前pending_input_id、proposal_id和source_version后，才以human_action=True调用dispatch。LLM工具保持默认False；已接受图片、已确认姿态及肯定底面/组件复核也要求该服务端标记，不能只信请求中的confirmed。reviewer从实际操作者身份取得。CLI的--human-action也只在真正人工复核后使用。
4. MeshStore按run_id隔离版本，文件摘要核对原始文件未变。工作流还须核对当前版本，不能把旧提案应用到另一个分支。原始和每轮只新增，最多两轮修复；clean与结构apply计轮数，定标不计轮数。
5. inspect.data.verdict是工具结论，不是新任务状态。blocked或needs_review不得合格交付；ready_for_slicer仍需当前版本的预览、实际切片和人工确认。最终成功继续由公共ModelTaskResponse规则判断。
6. 模型调用300秒、Blender单次120秒、模型自动重试0次；取消/超时会停止本工具子进程组。单卡worker并发1、累计活动900秒、队列/检查点/重启/去重仍由工作流成员实现。

## 3.坐标、尺度与检查口径

- 适配器的原始PLY为Z朝上的无量纲原生坐标；原官方TRELLIS.2 GLB另有(x,z,-y)导出转换，不能混用。TripoSR开发核验得到共享yaw=-90°/pitch=0°，不是逐图挑角度；当前映射仍待新增人工复核，运行时继续阻断未经复核的质量分。
- 定标只按已确认一个高度等比缩放，保存4×4变换与尺度来源。GLB按米/Y朝上写入，STL按毫米数值写入；STL本身无单位。GLB预览在前端显示毫米时应换算1000倍，不能将0.08米误显示为0.08毫米。
- 水密、法线、边界、非流形边/顶点、自交、薄壁分别记录。Blender薄壁是固定种子的逐面射线抽样，不是全局最小壁厚证明；法线/水密无效时正式壁厚not_run，临界±0.02毫米warn并阻断。原始探针命中数不能替代正式CheckResult。
- 悬垂为朝下法线与-Z夹角小于45°，打印平面底面排除，45°临界单列。平面接触面积不等同稳定；BedReview仍需对应网格的实际人工复核。
- 简化只在超过10万面时提供提案。比较三个固定视图、尺寸与拓扑，轮廓最低0.95、尺寸相对变化不超过1%；原始超大网格逐面检查未执行时明确记录，候选仍实际检查，不称为前后质量改善。结构预览/保形通过都不代表可打印。

## 4.Linux部署和复现

实际CPU环境：Python3.11.17，依赖见geometry可选组和[快照](../locks/geometry-linux.txt)。两个GPU模型继续复用原来的独立环境，不把本轮test-deps混入它们；模型子进程清理PYTHONPATH/PYTHONHOME并开启离线缓存。

Blender4.5.14/build62c1db4208e8及打印工具b42d6862固定在[工具锁定](../locks/linux-geometry-tools.json)。首次在Linux补libSM.so.6所需libsm6/libice6；实际已验证，Windows版不适用。用同版本发布镜像包及发布摘要，来源与SHA256均记录；官方直连403没有被描述成已修好。

新机器核对目录不存在后，可在项目根目录按以下固定来源部署；已通过的云端环境不用重装。模型环境和权重继续按既有安装记录准备，不在该步骤下载。

```bash
# 只有检查缺libSM.so.6时补运行库；不升级已通过环境。
apt-get install --no-install-recommends --no-upgrade libsm6 libice6
mkdir -p runtime/tools runtime/upstream
curl --fail --location --retry 0 --connect-timeout 10 --max-time 600 \
  https://mirrors.dotsrc.org/blender/blender-release/Blender4.5/blender-4.5.14-linux-x64.tar.xz \
  --output runtime/tools/blender-4.5.14-linux-x64.tar.xz
printf '%s  %s\n' 9ba871ff2ecd36526b77432745980b7e6664ecd0c7ca11c48849073dcfe06da3 runtime/tools/blender-4.5.14-linux-x64.tar.xz | sha256sum --check
tar -xf runtime/tools/blender-4.5.14-linux-x64.tar.xz -C runtime/tools
git clone https://github.com/blender/blender-addons.git runtime/upstream/blender-addons
git -C runtime/upstream/blender-addons checkout b42d68627734cb18af0e6f41537063984313a284
runtime/tools/blender-4.5.14-linux-x64/blender --version
```

检查器核对mesh_helpers.py的固定SHA256及Blender实际返回版本；不注册整套旧插件。API服务使用独立Python3.11工具环境，可按locks/geometry-linux.txt和geometry依赖安装；不能把这些目录加进Python3.10模型子进程。

模型配置示例只由操作者写入被忽略的配置文件，路径须改为本机真实路径：

```json
  },

```

候选配置将backend显式设为trellis2_candidate、Python指向trellis2环境。当前候选变体为native_geometry：复用pipeline.run，导出原生PLY；不含官方to_glb的重网格/PBR导出。它不是此前完整官方默认例，也不能直接冒充正式同机选型结果；官方历史产物保留，本轮没有切换第三模型。

```bash

python scripts/tools/geometry_cli.py --root <存储根目录> --config <操作者配置.json> --request <命令.json>
```
