## 1.本次交付与边界

## 2.后台如何处理

1. 仅新TRELLIS.2自动任务保存eye-local-v1，生成和原始GLB登记后进入独立眼部步骤。TripoSR及旧任务保持原路径，不补跑历史任务。
2. 在同任务原图上使用肤色连通域、暗眼线/眼白、双眼比例和位置找正面候选；没有可靠候选即跳过。这是确定性启发式，**不是通用动漫人脸识别模型**，不能保证刘海遮挡、闭眼、小眼、深色皮肤、多人或侧脸适用。
3. 对原始纹理网格作有限正交视角估计，结合轮廓和脸部底色选择视图。相反朝向区分不足、轮廓IoU<0.70、双眼位置偏差超过脸宽25%或眼型比例超出0.5～2倍时拒绝。此相机只用于外观试用，不作为已批准的质量测量映射。
4. 眼部三角形执行深度检查，只把对应原图眼部映到现有UV底色，边缘羽化。拒绝共享/镜像UV影响其他表面，修改纹素上限为图集2.5%，双眼覆盖不足也拒绝。技术超时90秒，不无限重试。
5. GLB直接追加内嵌PNG，并复制底色图像/纹理引用；原BIN字节、几何/UV访问器、节点、法线及金属/粗糙度等定义保持。独立解析增强件，逐字节核对原BIN前缀和非底色定义。原始文件不覆盖；增强件不称为原始PBR。
6. 跳过或失败时保留原始预览/下载，并记录实际原因。工具异常返回失败ToolResult；有效原件交付仍可完成，打印结论不变。错误的眼眶/眼球几何不是本步骤修复范围。

UV坐标按[Khronos glTF2.0规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#images)使用左上原点和纹素中心，不额外翻转V；本次已有原始GLB的JSON为单网格/单图元、普通浮点UV及内嵌PBR，满足入口格式，尚未实际投射。

主要实现：[局部投射](../src/image_to_3d_print/artifacts/eye_texture.py)、[自动图](../src/image_to_3d_print/workflow/automatic.py)、[契约](../src/image_to_3d_print/runtime_contracts.py)、[页面状态](../frontend/src/EyeTextureInfo.tsx)。

## 3.来源与兼容

original-glb-v1的artifact_id/source_sha256仍指原件，original_unchanged=true也只描述原件。兼容增加可空appearance_artifact_id；增强件必须为同任务/同根网格的repaired_mesh且derived_from原始产物。原件打印检查not_run，检查副本结论不能套给任何预览文件。已更新的运行时Schema及前端类型读取新增可空字段；旧记录缺字段按空值读取，旧客户端需同步类型。

runtime.resources.eye_texture记录applied/skipped/failed、原因、源/增强摘要、原图/准备图摘要、策略/库版本、眼框、估计视角与实际修改纹素；成功才登记增强产物。任务/网格引用通过公共ToolOutcome/证据记录。旧记录不修改幂等请求摘要。眼部节点与生成节点分开，恢复不因该步骤重新执行重建；取消/超时按已有worker停止规则处理，本轮未重测这些分支。

## 4.你在网页怎么测试

1. 保持云端正常模式和已有连接，刷新网页；选择TRELLIS.2，上传同一人物原图并填写原有参数后提交。没有新增勾选或中途操作。**旧任务不会自动重新处理，刷新旧任务不会出现新修正。**
2. 完成后查看“眼部局部贴图试用”。只有“已生成局部修正版”才表示实际执行并产生副本；“未应用”或“失败”会说明原因，不能当作修正成功。
3. 检查虹膜颜色、高光、眼白和位置；转动模型查看斜视角是否拉伸/错位，检查脸、头发、服装、材质和几何是否误变。新结果尚不保证有效。
4. 主预览/“下载GLB”按钮在增强件可用且开关开启时使用增强件，否则使用原件。下载仍只由按钮触发。“本任务文件”保留原始GLB用于对照，不自动下载。
5. 告诉我“通过”或“回退”，可附眼部截图。如果定位被跳过，请提供页面原因；不会以增加面数冒充眼部修复。

## 5.立即回退

无需删代码、重新生成或改任务数据库。后台关闭开关后，网页下一次任务轮询就恢复原始预览及主下载；已下载到电脑的增强文件不会被替换。增强件留档，质量报告中的历史执行记录保持。

云端项目目录内执行：

```bash
runtime/envs/backend/bin/python deployments/official-20261021-01/scripts/tools/set_eye_texture.py --config runtime/config/backend.json --mode off
```

重新启用将off改为on。开关只写入/删除存储根目录的eye-texture.disabled，API/worker动态读取，不重启、不取消用户任务、不控制实例开关机。若服务端配置eye_texture_enabled=false，删除标记也不会越过配置启用。

此命令已开发，**本轮未实际切换/浏览器验证**，由后续用户反馈决定是否执行。用户已授权效果不好时回退，不需要再次索取同一权限。
