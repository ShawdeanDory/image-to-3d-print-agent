## 1.Pydantic输入、输出、错误与证据模型

唯一机器可执行定义为[src/image_to_3d_print/schemas](../src/image_to_3d_print/schemas/__init__.py)，导出见[JSONSchema](../schemas/contracts-v1.schema.json)。下表是字段摘要；实际字段和validator以公共定义为准。P1实现输入、响应及工具返回封装校验；具体后端参数/工具data在接入阶段另加对应校验，不声称已有工具适配器或HTTP服务。

| 模型 | 核心字段与用途 |
| --- | --- |
| `ModelTaskRequest` | `image_asset_id`、`height_value`、`height_unit`、`scale_source`、`scale_evidence_id`、`orientation`、`printer_profile_id`、`description` |
| `AssetRecord` | 合法图片的asset_id、POSIX相对路径、真实类型、字节数与像素尺寸；限制10MiB/4096像素 |
| `Orientation` | up_axis与confirmed；已确认必须给出朝上轴 |
| `TaskData` | 请求、状态、打印配置、检查和切片确认的结构化集合 |
| `ToolResult` | 固定tool_name、run_id、成功标志、产物/证据引用、结构化data与错误 |
| `MetricValue` | 指标名、measured/not_run/unknown、有限非负值或null、单位与原因 |
| `BudgetPlan` | 草稿/已确认、准备/推理上限、重试0～1、费用上限、确认人；缺项不放行 |
| `DatasetCase` | 输入/蒙版、来源/许可/对象组/划分、预期行为、请求模板和not_run状态 |
| `DatasetManifest` | 数据/契约版本、划分策略和任务列表，禁止对象/文件跨划分 |
| `SplitPolicy` | 每划分数量与正常数量，数据清单必须满足声明 |
| `ModelTaskResponse` | 统一响应中的标识、状态、数据、证据、数据集、产物、警告、事件与错误 |
| `WorkflowState` | `run_id`、`stage`、`status`、`pending_input_id`、`pending_input_type`、`mesh_version`、`repair_round`、`artifacts`、`checks`、`warnings`、`error` |
| `PrinterProfile` | `profile_id`、`version`、`profile_kind`、`process`、`material`、`nozzle_mm`、`layer_height_mm`、`min_wall_mm`、`build_volume_mm`、`slicer_version`、`supports_policy` |
| `MeshInspection` | `mesh_version`、`unit`、`dimensions_mm`、`volume_mm3`、`volume_reason`、`normals_consistent`、`component_count`、`watertight`、`boundary_edge_count`、`non_manifold_edge_count`、`non_manifold_vertex_count`、`checks` |
| `CheckResult` | `name`、`status`、`value`、`threshold`、`unit`、`tool_version`、`evidence_artifact_id`、`details` |
| `ArtifactRecord` | `artifact_id`、`run_id`、`mesh_version`、`kind`、`relative_path`、`created_at`、`derived_from`、`unit` |
| `ErrorInfo` | `code`、`message`、`details`；明确错误来源及当前阶段，不通过语言模型编造原因 |
| `EvidenceRecord` | `evidence_id`、`source_type`、`source_id`、`run_id`、`mesh_version`、`artifact_id`、`locator`、`created_at`、`summary` |
| `ExperimentRecord` | 复现/对比记录的版本、数据、执行机、参数、命令、资源、退出码、失败与证据；字段见第5节 |
| `SlicerConfirmation` | `pending_input_id`、`mesh_version`、`result`、`slicer_version`、`printer_profile_id`、`dimensions_mm`、`supports_enabled`、`layer_preview_asset_id`、`confirmation_artifact_id`、`notes` |

### 输入与输出校验

- `image_asset_id`引用服务端实际存在的合法图片；不允许客户端传入任意本地路径或命令。
- `height_value`为正数或缺省；单位白名单为`mm`、`cm`，换算后内部为毫米。高度或单位缺失时可创建任务并追问，负数和非法单位拒绝。
- `scale_source`区分`user_target`与`measured_object`；没有依据时保持未知并追问，不能默认为真实测量。
- `orientation`至少含`up_axis`与`confirmed`；方向未确认时不能完成定标交付。
- `printer_profile_id`必须引用明确版本的打印配置；未知打印空间不能作为通过证据。
- `CheckResult.status`仅为`pass`、`fail`、`warn`、`not_run`。它是检查项结论，与任务状态分开；未执行的值为`null`并说明原因。
- `volume_mm3`仅在尺度、封闭性和方向有效时填写，否则为`null`；不把未知物理量写为0。
- ID、枚举、引用关系和数值范围均由Pydantic及确定性引用校验处理，不接受模型自由生成的任意状态。

### 错误模型

| 字段 | 约定 |
| --- | --- |
| `code` | 非空稳定错误码，不随语言说明变化 |
| `message` | 给用户的具体错误或待补输入说明，不包含密钥和未脱敏日志 |
| `details` | 结构化上下文，如字段名、阶段、工具返回码、预算和相关证据ID；无数据时为空对象 |

错误码为`ErrorCode`白名单，额外含`REFERENCE_NOT_FOUND`、`STATE_CONFLICT`、`BUDGET_NOT_CONFIGURED`；原有项包括`INVALID_IMAGE`、`INVALID_ARGUMENT`、`MODEL_NOT_CONFIGURED`、`TOOL_UNAVAILABLE`、`GPU_OUT_OF_MEMORY`、`TOOL_TIMEOUT`、`MESH_NOT_PRINTABLE`、`REPAIR_LIMIT_REACHED`、`SLICER_VALIDATION_FAILED`及`WORKER_RESTARTED`。缺尺度/姿态使用pending_input_type的height、height_unit、scale_source、orientation及待补说明；这些不是ErrorInfo.code，不把可继续任务直接判为failed。

### 证据模型

| 字段 | 约定 |
| --- | --- |
| `evidence_id` | 单条证据的稳定ID |
| `source_type` | `input`、`tool`、`measurement`或`human` |
| `source_id` | 图片、工具调用、测量记录或确认记录的实际ID |
| `run_id` | 所属执行，必须和任务一致 |
| `mesh_version` | 涉及的具体网格版本；原始输入没有网格版本时允许为空 |
| `artifact_id`、`locator` | 实际文件/报告引用及其中的检查项、面索引等位置；不伪造链接 |
| `created_at` | 带时区的时间戳 |
| `summary` | 基于证据的事实摘要，不得扩大为未经检查的可打印结论 |

检查、修复和切片证据的网格版本必须匹配；语言模型生成的一句话不能替代工具报告或用户确认。

DOC-006只澄清适用范围，不新增字段、状态或错误码：产品正常输入限简单摆件，范围外请求在后续M02/M06按现有错误/待补机制解释并停止或请求换图，不能调用重建后直接宣称合格。官方复杂T样例的ExperimentRecord.status=succeeded仅表示official_inference执行成功，不是ModelTaskResponse的产品任务成功；原记录和契约1.0.0均保持。尺度/姿态追问、修复确认、恢复和证据关联仍须由小组实现，不能把已有Pydantic结构当成Agent已实现。

## 2.统一响应与运行状态

公共字段：`request_id`、`task_id`、`run_id`、`status`、`data`、`evidence`、`datasets`、`artifacts`、`warnings`、`events`和`error`。events当前为轻量文字记录列表，增量事件ID/持久化接口在P5实现前须另行版本化定义，不能据此声称已有事件服务。未使用的集合返回空数组，成功或无异常时`error=null`，发生错误时使用`ErrorInfo`。

| 运行状态 | 含义与主要转换 |
| --- | --- |
| `queued` | 等待worker；开始执行进入`running`，取消前可直接结束为`cancelled` |
| `running` | 正在执行节点；可暂停、成功、失败或响应取消请求 |
| `waiting_for_input` | 等待尺度、姿态、修复确认或切片结果；有效输入后重新排队，由worker恢复 |
| `cancel_requested` | 正在停止当前子进程并保存已有结果 |
| `succeeded` | 必需检查、预览、切片确认与产物记录全部完成 |
| `failed` | 执行失败或阻断缺陷无法处理；保留诊断与失败证据 |
| `cancelled` | 已取消，停止后续工具调用并保留已有版本 |

不增设同义状态；具体节点使用`stage`。终态不直接恢复，重试创建新`run_id`。缺尺度的无单位预览不代表定标完成或任务成功。

`pending_input_id`定位当前等待项；重复提交已处理输入返回已处理结果，不再次推进。替换图片创建新任务，单纯补尺寸或确认姿态恢复原任务，不重复重建。

## 3.REST接口草案

| 方法与路径 | 用途 | 约定 |
| --- | --- | --- |
| `POST /api/v1/assets` | 上传图片或切片证据 | 校验实际格式与扩展名，返回`asset_id` |
| `POST /api/v1/model-tasks` | 创建任务 | 返回HTTP202及`run_id`，不等待GPU计算结束 |
| `GET /api/v1/model-tasks/{run_id}` | 查询任务 | 返回统一状态、阶段、待补项、检查与产物 |
| `GET /api/v1/model-tasks/{run_id}/events?after={event_id}` | 增量查询事件 | 第一版轮询；不引入WebSocket |
| `POST /api/v1/model-tasks/{run_id}/inputs` | 补尺度、姿态或修复确认 | 校验当前等待项及schema后恢复工作流 |
| `POST /api/v1/model-tasks/{run_id}/slicer-confirmation` | 提交切片结果 | 引用当前网格和实际分层证据，失败不转为成功 |
| `POST /api/v1/model-tasks/{run_id}/cancel` | 请求取消 | 可重复调用，终态返回现有状态 |
| `GET /api/v1/model-tasks/{run_id}/artifacts/{artifact_id}` | 预览或下载 | 仅定位当前任务实际产物，不能任意读取磁盘 |

HTTP422表示输入校验失败，404表示引用不存在，409表示请求与当前阶段或版本冲突；已进入任务的异步工具失败通过任务状态和`ErrorInfo`返回。P1已离线核对这4类边界错误的状态码映射，并拒绝把异步工具错误映射为边界HTTP错误；没有HTTP服务器或端点测试，实际响应在P5验证。

创建请求示例：

```json
{
  "image_asset_id": "asset_example",
  "height_value": 80,
  "height_unit": "mm",
  "scale_source": "user_target",
  "orientation": {"up_axis": "z", "confirmed": false},
  "printer_profile_id": "fdm_pla_04_demo_v1",
  "description": "生成简单摆件，保留主体轮廓"
}
```

这是设计示例，示例ID不代表已有上传文件或打印配置。演示高度80毫米必须经用户确认，不能静默填入缺失尺度。

## 4.工具返回、字段与版本纪律

- 工具适配器固定名称和参数，返回相应输出模型或`ErrorInfo`，同时保留证据引用；不能用任意字符串表示成功。
- 路径只由服务端管理，单位统一为毫米，进入Blender时显式转换场景单位。
- 公共schema现为唯一可执行契约；接口、实现、测试和本文件同时更新，不直接改名已发布字段。
- 保存契约版本、变更原因、影响模块与回归结果。当前v1.0.0已验证初始结构/跨字段/引用契约；没有旧版服务消费者或跨版本API兼容性证据。

| 版本/日期 | 变化 | 验证状态 |
| --- | --- | --- |
| 草案v0.1/2026-10-16 | 从总体方案迁移字段/状态/API，补明确的响应、错误与证据模型 | 文档设计；Pydantic实现及契约测试未执行 |
| 草案v0.2/2026-10-19 | 新增ExperimentRecord设计及来源、版本、比较和未知值规则；REST/状态保持 | 仅文档；当时P1尚未实现 |
| v1.0.0/2026-10-19，2026-10-20交付 | 20个公共模型及引用/文件/预算/冻结校验，新增测量证据、切片确认artifact和数据模型；JSONSchema自动导出 | 57项离线测试及静态检查通过；用户明确确认阶段验收，实际导读范围单列；API和实际模型未执行 |

## 5.P1实验记录设计

P2A-MEASURE-001增加内部`MeasurementRequest`/`MeasurementReport`，定义在`src/image_to_3d_print/measurement.py`，不加入20个公共业务模型或改变JSONSchema1.0.0。请求含项目内网格/可选蒙版路径、后端、已知几何/待核验映射、旋转和来源；返回公共MetricValue、ToolResult、ArtifactRecord和EvidenceRecord。`ToolResult.tool_name=inspect`、data.measurement_kind=silhouette_diagnostic只表示诊断，不产生MeshInspection打印合格结论。只有有依据的固定几何可返回measured；真实后端当前强制not_run/null，蒙版缺失不能猜填。CLI是可信操作者入口，不接收业务HTTP请求。字段和命令见[CPU测量报告](CPU坐标与轮廓测量验证.md)。

ExperimentRecord用于内部实验清单，不要求产品用户提交源码或机器路径，不新增REST端点/任务状态。以下字段已在P1实现并进行离线测试；后续真实模型运行结果分别归档，TripoSR的两例记录已保存于evals/results。P2A-BASE-001只有基础安装和CPU检查，使用独立环境证据，不创建official_inference成功记录或变更业务契约。

P2A-CPU-001同样只记录无卡环境、权重/缓存完整性、导入和输入预检，不创建候选official_inference成功记录。用户取消的是工作整体时限，内部准备证据以time_limit_s=null、time_policy=user_waived表示；不把业务BudgetPlan的缺配置校验改为放行，也不填造“已确认无限预算”。

P2A-GPU-001现已实际完成官方例，新增[1条真实ExperimentRecord](../evals/results/p2a-20261020-trellis2.json)，按现有公共模型校验通过。case_id指上游官方T样例，不冒充P1的30例；budget_ref引用[操作者授权策略](../evals/budgets/p2a_user_execution_policy.json)，该策略不是产品BudgetPlan，不宣称require_ready通过或更改业务预算阻断。仅取得整体计时的区间按实际口径记录，加载/纯推理等未单独采集的数值保持null/not_run；GLB有效和可打印验收分开。

| 字段组 | 必需内容与校验方向 |
| --- | --- |
| 身份与来源 | `experiment_id`、`experiment_type`、`run_id`、`case_id`、`dataset_version`、`split`、`executed_by`、`evidence_origin`、`created_at`；区分user_submitted、agent_executed与仅用于结构正例的offline_fixture，标明日期/时区来源 |
| 实验类型 | `official_inference`、`model_comparison`、`repair_comparison`、`workflow_comparison`；采集环境单独关联环境证据，不冒充模型运行 |
| 版本 | `backend_id`、`project_commit`、`upstream_commit`、`submodule_revisions`、`weights_revision`、`environment_ref`、`schema_version`；P2-A模型运行的关键版本不得缺失 |
| 配置 | `preprocessing_ref`、`parameters`、`seed`、`hardware_ref`、`budget_ref`、`printer_profile_id`及确认尺度；模型固有参数分别保存，参数名和值必须受所选后端校验 |
| 执行与结果 | 实际命令/入口、`exit_code`、输出网格/日志证据、`status`、`error`和比较组ID；只引用实际存在且属于对应执行的产物，重建生成与打印合格分开 |
| 度量 | 各段耗时（秒）、峰值分配/预留显存（MiB）、nvidia-smi占用及口径、质量/几何/切片检查；未采集为null，未执行为not_run，不能填0，实测0仅用于已测得为0的量 |
| 比较关联 | `comparison_group_id`、`baseline_run_id`、`changed_factor`、`metrics_protocol_version`、`release_frozen`、`release_ref`；P3/P4同原始输入、同后端；实际保留集执行必须引用冻结版本 |

失败保留在比较分母内；官方默认和低显存适配分别标识。命令和日志不得包含凭据。实验协议与门槛引用[评估设计第5节](评估设计.md#5复现对比与工作流实验规则)，不在接口文档另设阈值。
